## Skill routing

When the user's request matches an available skill, ALWAYS invoke it using the Skill
tool as your FIRST action. Do NOT answer directly, do NOT use other tools first.
The skill has specialized workflows that produce better results than ad-hoc answers.

Key routing rules:
- Product ideas, "is this worth building", brainstorming → invoke office-hours
- Bugs, errors, "why is this broken", 500 errors → invoke investigate
- Ship, deploy, push, create PR → invoke ship
- QA, test the site, find bugs → invoke qa
- Code review, check my diff → invoke review
- Update docs after shipping → invoke document-release
- Weekly retro → invoke retro
- Design system, brand → invoke design-consultation
- Visual audit, design polish → invoke design-review
- Architecture review → invoke plan-eng-review
- Save progress, checkpoint, resume → invoke checkpoint
- Code quality, health check → invoke health

## Deploy Configuration (configured by /setup-deploy)

- **Platform**: Cloudflare Pages
- **Pages project**: `cloudflare-topology`
- **Production URL**: https://cloudflare-topology.pages.dev
- **Deploy artifact**: `_deploy/` (gitignored; generated locally by `main.py` or `server/server.py`)
- **Deploy trigger**: manual via wrangler (no CI workflow)
- **Deploy status**: HTTP health check on production URL
- **Merge method**: squash (GitHub default)
- **Project type**: static site (HTML + vendored JS), generated by Python

### Custom deploy hooks

- **Pre-merge**: none
- **Build artifact**: `python main.py --no-browser` regenerates `network_topology.html` and copies to `_deploy/`
- **Deploy trigger**: `npx wrangler pages deploy _deploy --project-name=cloudflare-topology --commit-dirty=true`
- **Deploy status**: `curl -sf https://cloudflare-topology.pages.dev -o /dev/null -w "%{http_code}"`
- **Health check**: https://cloudflare-topology.pages.dev

### Notes

- The Flask server (`server/server.py`) runs locally and handles scheduled regeneration. It is NOT deployed to Cloudflare.
- Only the static output in `_deploy/` ships to Pages.
- Cloudflare Pages auto-promotes pushes on the main branch of a connected Git repo, OR accepts direct uploads via wrangler. This project uses direct uploads because `_deploy/` is gitignored.
